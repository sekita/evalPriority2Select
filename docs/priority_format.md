# 優先度表（tableP）の見出し形式

## 1. 役割

優先度表は、評価表にある評価項目を「どの順番で選択木の分岐に使うか」を指定する入力ファイルである。

同じ評価表でも優先度表を変えることで、異なる選択方針の選択木を生成できる。

## 2. 基本形

```text
任意のタイトル

# 順位
## 評価項目

# 1
## 最優先の評価項目

# 2
## 2番目の評価項目

# 3
## 3番目の評価項目
```

重要なのは、**最初の `#` ブロックがヘッダとして必ず読み飛ばされる**ことである。したがって `# 順位` / `## 評価項目` のようなヘッダを必ず置く。

## 3. 順位ブロック

2番目以降の各 `#` は順位である。順位は整数として解釈され、数値の小さい順に処理される。

```text
# 1
## 高効果

# 2
## 低リスク
```

順位はファイルの記載順そのものではなく、整数として昇順に並べ直される。同順位の場合だけファイル内の出現順を保つ。

仕様上は `0`、負数、符号付き整数も受け付けるが、通常は `1, 2, 3, ...` と連番にするのが分かりやすい。

## 4. 評価項目名

各順位ブロックの最初の `##` に、評価表ヘッダに存在する評価項目名を書く。

```text
# 1
## 導入の早さ
```

評価表に存在しない項目を書くとエラーになる。

同じ評価項目を複数回指定した場合は、先に採用されたものを使い、後の指定は警告付きで無視される。

1つの順位ブロックに `##` が複数ある場合も、最初の1つだけを使い警告する。

## 5. 評価表にある項目を省略した場合

優先度表に指定しなかった評価項目は分岐に使用されず、警告が出る。

これは「その評価項目を今回の選択ロジックでは使わない」という意味になるため、意図的に省略することも可能である。

優先度表がヘッダだけの場合、優先度リストは空となり、選択木は評価項目で分岐せず、全選択肢をルートの葉に列挙する。

## 6. 見出しを書くときの規則

`#` と `##` は必ず行頭から書く。

```text
# 順位
## 評価項目
# 1
## 高効果
```

行頭へ空白を置くと見出しとして扱われず、警告となる。

`###` 以上は入力構造としては使用しない。
