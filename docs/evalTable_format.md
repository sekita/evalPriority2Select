# 評価表（tableE）の見出し形式

## 1. 役割

評価表は、複数の選択肢を複数の評価項目で評価した内容を、Markdown の `#` と `##` だけで表す入力ファイルである。

最初の `#` ブロックがヘッダ、それ以後の `#` ブロックが1つずつ選択肢になる。

## 2. 基本形

```text
任意の説明文（なくてもよい）

# 改善案
## 評価項目1
## 評価項目2
## 評価項目3

# 選択肢A
## 評価値A1
## 評価値A2
## 評価値A3

# 選択肢B
## 評価値B1
## 評価値B2
## 評価値B3
```

`#` や `##` で始まらない説明文や空行は無視される。

## 3. ヘッダブロック

最初の `#` が表の第1列見出しに相当する。通常は `# 改善案`、`# 候補`、`# 選択肢` などとする。

その直下の `##` が評価項目である。

```text
# 改善案
## 高効果
## 低導入費用
## 低運用費用
## 導入の早さ
## 低リスク
```

この `##` の出現順が列順を決める。上の例では、

1. 高効果
2. 低導入費用
3. 低運用費用
4. 導入の早さ
5. 低リスク

の順である。

## 4. 選択肢ブロック

2番目以降の `#` が選択肢名であり、その直下の `##` が評価値である。

```text
# AI導入
## ◎
## △
## ◎
## △
## △
```

この例はヘッダの列順に対応しており、「高効果=◎、低導入費用=△、低運用費用=◎、導入の早さ=△、低リスク=△」を表す。

評価値の個数がヘッダの評価項目数より少ないとエラーになる。多い場合は警告を出し、超過分を無視する。

## 5. 標準の評価値

標準の並び順は良い順に次のとおりである。

| 評価値 | 出力順 |
| --- | ---: |
| `◎` | 1 |
| `〇` | 2 |
| `△` | 3 |
| `×` | 4 |

次の異体字は比較時に同じものとして扱われる。

| 入力 | 比較上の扱い |
| --- | --- |
| `○`, `◯` | `〇` |
| `✕`, `x`, `X` | `×` |
| `▲` | `△` |

`ｘ`・`Ｘ` のような全角英字は `×` には変換されず、未知の評価値となる点に注意する。

標準4値以外の文字列も評価値として使用できる。未知の評価値は標準4値より後ろに並び、評価表全体での初出順を使う。

## 6. 見出しを書くときの規則

見出しは `#` を必ず行頭に置く。

```text
# 正しい
## 正しい
```

次のように行頭へ空白を入れてはならない。

```text
 # 誤り
  ## 誤り
```

このような行は見出しとして無視され、警告が出る。

レベル1 (`#`) とレベル2 (`##`) だけを入力構造として使う。`###` 以上は想定外として無視され、警告になる。

## 7. 評価項目名の照合

優先度表に書いた評価項目名は、評価表ヘッダの評価項目名と照合される。

照合時には NFKC 正規化に加え、半角スペース、全角スペース、タブを除去する。このため全角・半角や空白の差の一部は吸収される。

ただし、利用者が意図を確認しやすいよう、評価表と優先度表では同じ表記を使うのが望ましい。
